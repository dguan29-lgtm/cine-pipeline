# 实战事故登记簿（Incident Log）

> 定位（2026-10-03 建）：本 Skill 的规则大多来自移植与推演，**实战翻车案例是最稀缺的资产**。本文件是"事故回写三件套"（维护纪律第 4 条）的快速登记入口——用户或 QC 现场发现翻车，先在这里花 1 分钟登记，再按晋升纪律决定是否回写进规则文件。
> 加载时机：发生生成事故/QC 检出失败/用户反馈翻车，或每月例行回顾时。日常创作不加载。

## 快速登记模板（复制即用，1 分钟填完）

```text
### INC-YYYYMMDD-NN ｜ 一句话现象
- 日期 / 项目 / 镜头或段落：
- 阶段：试产 / 批量生成 / QC / 后期
- 现象（可观察，带时间码或截图）：
- 当时用的提示词关键段（引用，不全文贴）：
- 模型 / 入口 / 参数：
- 根因定性：规范缺陷 / 模板缺失 / 执行错误 / 模型能力边界 / 未明
- 修复落点：哪个文件哪节（未修复填"待定"）
- keep/revert 声明：什么证据出现时应**推翻**本条结论（必填，防空规则永久化）
- 状态：单次登记 / 已二次复现 / 已晋升规则
```

## 晋升纪律（防"一次事故立一条法"）

1. **单次登记只进本文件**，不改规则。"Do not create a rule from one ambiguous result."
2. **晋升规则需满足其一**：同一失败族独立复现 ≥2 次；或单次事故能指认明确的机制缺陷（而非"效果不好"）。多变量同时改动得出的因果结论不算证据（"不能声称某提示词短语导致了效果，如果同时改了好几个变量"）。
3. **禁形容词经验**："更电影感""更自然"类无法验证的"教训"不许登记，必须落成可观察条件。
4. **归因先于指责**：定性"模型不行"前，先排查提示词超载、参考图冲突、不支持的任务模式、资产质量、工作流错误五层。
5. **晋升动作**：按三件套写进目标文件（现象→根因→修复落点），本条目状态改"已晋升规则"并标注落点；每月回顾一次，把"已二次复现"但未晋升的条目集中处理。
6. **反向清理**：keep/revert 声明被触发的规则，从规则文件移除或降级回本文件，标注推翻证据。

## failure_conditions 字段约定（2026-10-03 自进化库吸收）

凡从本簿晋升进规则文件的新规则，必须带一行**失效边界**：该规则在什么场景不适用、有什么副作用。规则只写 when/what 不写"何时不灵"的，视为不完整。
