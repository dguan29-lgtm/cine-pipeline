# 批量生成与 Dailies QC（Batch Generation & Shot Lock）

> 进入时机：试产三镜通过、生成参数锁定后。

## Batch order

Generate by dependency and risk, not screenplay order:

1. identity/location anchors;
2. recurring dialogue/performance setup;
3. difficult action/VFX;
4. ordinary coverage;
5. transitions, inserts and repair shots.

This exposes systemic failures before most of the budget is spent.

## Dailies review

Score observable criteria only:

| Dimension | Questions |
|---|---|
| story | is the intended beat readable without explanation? |
| identity | correct person, wardrobe, prop and location? |
| performance | objective and reaction legible; no unwanted expression/lip movement? |
| action | start, contact/cause and result physically readable? |
| continuity | matches ledger and neighboring shots? |
| image | anatomy, geometry, text, flicker, focus and artifacts acceptable? |
| sound | required dialogue/SFX present, clean and replaceable? |
| editability | correct duration, direction, handles and cut points? |

Disposition: `accept`, `accept-with-post-fix`, `retry`, `alternate-route`, or `drop/rewrite`.

**意图加权三级严重度（2026-10-03 shuohao output-review 库吸收）**：不打统一分数，按该镜头**创作意图**加权判级——
- `Blocking`：破坏叙事可读性或身份/空间成立（换脸、口型缺失、动作因果断裂）→ 不可锁定；
- `Major`：明显缺陷但不挡理解（质感漂移、节奏偏慢）→ accept-with-post-fix 或 retry；
- `Minor`：挑剔级问题（轻微伪影、非关键帧闪烁）→ 记录后放行。
每条失败记录：镜头/时间码 + 观察 + 严重度 + **归因层**（prompt 写法 / 参考图 / 资产质量 / 工作流 / 平台能力 / 编码压缩 / 未明——**归因先于指责**：定性"平台/模型不行"前必须排除前四层）。

## 素材取证（本地视频文件，2026-10-03 接入 video-frame-study）

> 触发：用户发来**本地视频文件路径**要审片/定位问题时。不再纯靠用户语言描述——先取证，再诊断。

1. **调 `video-frame-study` 技能跑其自带扫描脚本 scan_video.py**（脚本在该技能目录内；操作细节、环境、阈值以该技能为 SSOT，此处不重复定义），一次拿到：元数据、切点列表、每镜头代表帧、2s 网格帧、画面能量+音频 RMS 曲线。
2. **数据先行**：从切点密度读节奏结构、从能量曲线找静止段与爆点、从音频包络找声画错位——先形成假设，再批量 Read 关键帧验证。
3. **证据升级置信度**：帧级截图+时间码可把多数 `medium/low` 结论升到 `high`；诊断输出的「可见证据」段必须引用具体时间码与帧，不再接受"大概中间那段"式描述。
4. **确定性检查清单**（取证时顺带核，来自 2026-10-03 output-review 吸收）：元数据（时长/分辨率/帧率是否等于锁定参数）→ 切点位置（是否出现在设计的剪辑点）→ 黑帧/冻结帧（能量曲线归零段）→ 音频有无与电平（RMS 曲线）。
5. 用户只给在线链接或不方便提供文件时，仍走语言描述路径，置信度相应标注。

## Evidence confidence（证据置信度，2026-09-18 AI导演审片库吸收）

每条 dailies 结论在处置之外必须附置信度标签，防止"评分掩盖证据不足"：

- `high`：素材全程可读、采样覆盖完整时长、上下文（剧本/分镜/参考图/原始 Prompt）齐全。
- `medium`：采样不全、疑似压缩或低码率伪影、创作意图不明。
- `low`：关键时段不可读，或用户反馈无法从素材本身验证。

纪律（与八维评分并行生效）：

- **观察与推断分离**：只报告可见现象；推断内容标【待确认】，不编造时间点与参数。
- **不反推镜头参数**：无元数据时只写「呈广角透视倾向」「背景压缩感较强」，禁止写"24mm / f1.8"。
- 面部不可见、音频不可读、参考素材缺失时，对应维度标「未充分检查」，**不得默认满分**。
- 高分 + 低置信 ≠ 通过。置信度低时，明确列出还缺什么证据（关键帧 / 带时间码截图 / 原始 Prompt / 对标参考），先补证据再下结论。

## 看不懂时：找到信息最早丢失的位置

用户说“剧本能懂，视频看不懂”时，先保留其首次困惑，再沿同一事件对照当前正文、实际分镜/请求、源素材与采用区间。借用项目已有事件或台词标识；小任务直接用原句/动作定位，不为检查另建一套账。

| 对照结果 | 首先处理 |
|---|---|
| 正文已写明，分镜只写“发现真相”等标签 | 把必要事实安排成可辨的动作、物件、声音或前后关系 |
| 分镜有安排，生成素材没有呈现 | 修实际参考、请求、表演或对应素材 |
| 源素材有，当前剪辑删掉、遮住或混音压住 | 先检查采用范围、切点、布局与混音 |
| 对照证实正文缺少必要前提 | 才在授权范围内回编剧环节定向修改 |

区分“眼前行动必须懂”“有效前情已交代”“刻意未知”“无关细节”。不知道幕后是谁可以是悬念；不知道谁在向谁求助可能是理解缺口。人物卡、文件名和作者说明不能证明观众已经得到信息。

例：原片拍到了店主把一枚筹码递给顾客，粗剪只留下递出前与接到后的画面，观众误以为筹码凭空出现。先核实是否确实裁掉了交接，以及已有声画能否补足，再决定恢复采用范围；不先增加旁白或改写筹码来源。若只有文字反馈，说明这是待核实假设，不伪称看见丢帧。

需要独立理解检查时，只给未参与设计的审阅者实际材料和允许的前情，先让其复述发生了什么及不确定处，再定位问题。模型审阅不等于真实受众测试；看过答案后才懂，与首次就懂分开记录。不默认每镜启动代理或加审核轮次。

### 采用结论绑定同一版、同一范围

记录实际采用文件/版本（有 hash 则沿用）、源入出点和实际检查范围。A版脸正确、B版台词正确，不能拼成“已全部通过”；要检查最终实际组合是否同时满足要求。改采用、换音轨或重生成后，重查受影响的信息及相邻切点，未受影响部分保留既有检查。

复查在目标尺寸、正常速度下连看关键事件，并听当前声音。截图只能支持对应可见事实，转写只能辅助核字，二者都不能代替完整动作与语气检查。停止尝试不等于通过；已确认的硬伤不能因额度用完降为可采用，未解决范围如实保留。

方法来源：DramaForge [09 审核与返修](https://github.com/iuydd/drama-forge/blob/baade86bd17363be930f1402d09996c1f5cbc091/references/09-review-repair.md)。这里补充信息断点与证据绑定，仍沿用本套件既有返修范围和授权，不接入上游 G0–G4 或固定轮次。

## 审美翻译层（Aesthetic translation layer，2026-09-18 AI导演审片库吸收）

> 分工（SSOT）：八维评分管**验收处置**——"这条 take 能不能用"；审美翻译层管**诊断解释**——"为什么不好看、怎么改"。两者不重复打分，审美诊断不混入八维扣分，只有专业关系明确破坏叙事可读性或对标指标时才反馈到处置意见。

**触发条件（任一）**：用户表达模糊不满（"有点假""很平""不像电影""运镜很 AI"）；八维全过但对标对比不达标（stage3 防坑清单第 25 条）；用户直接问"为什么不好看 / 缺什么 / 属于什么风格"。

**诊断十维度**（只展开影响最大的三项，按"最破坏目标表达 > 最影响观众感受 > 最值得优先返修"排序，其余进次要建议）：

| 维度 | 查什么 |
|---|---|
| 1 人物运动与重量感 | 步态节奏、重心转移、脚底接触、启停加速度、衣发滞后、碰撞反馈——"飘着走"常来自脚底滑动/躯干等速平移/重心不起伏 |
| 2 景别与人物关系 | 当前景别是否提供叙事所需信息；支配度、头顶/视线/运动空间、截肢位置 |
| 3 机位、距离与透视 | 视点高低、正侧关系、视差、透视夸张或压缩是否支持力量/亲密/疏离/空间方向 |
| 4 运镜与摄影机惯性 | 运镜有无观察/跟随/揭示/情绪动机；等速运动、无缓入缓出、摄影机"预判"人物动作都是生成感来源 |
| 5 调度与空间叙事 | 人物出入画、视线、轴线、屏幕方向、前中后景、遮挡——动作合理但"为何走、走向哪"不清，镜头同样不成立 |
| 6 光线、曝光与色彩 | 主光方向、明暗层级、主体背景分离、肤色、混合色温、高光溢出、暗部堵塞 |
| 7 焦点、景深与质感 | 焦点目标与转移、景深边界、边缘伪散景、跨帧纹理稳定 |
| 8 剪辑与节奏 | 切点是否由动作/视线/信息/情绪推动；一镜到底查内部节拍而非要求切点 |
| 9 表演与情绪可读性 | 触发—压抑—释放—回应的过程是否可见；结果存在（哭）≠过程成立 |
| 10 声画关系（音频可读时） | 口型/动作同步、环境声空间、声音转场；音频不可读明确标未检查，不从画面推断。**"有台词无口型"（说话者嘴唇不动）为硬失败，不可锁定镜头**——返修阶梯按 stage3 防坑清单第 37 条执行：补口型字段与情节开口动作 → 升景别拉近面部 → 清出台词窗口内大肢体动作 → 换路由 |

**证据链六段式**（每条诊断的固定输出结构，缺段=未完成诊断）：

```text
普通观感：用户原话（"走路有点飘"）
可见证据：时间范围 + 实际看到的现象（00:02.1–00:03.4，双脚接触点持续后移但身体近似恒速前移）
专业判断：涉及哪层视觉关系（脚底锁定、重心起伏与接触阴影未形成同一套重量反馈）
作用机制：为什么削弱表达（缺少"踩地—承重—推进"反馈，运动被读成漂移）
修改方向：最小可验证调整（锁定脚底接触帧、加每步重心下沉、摄影机跟随带延迟并在启停缓入缓出）
置信度：high / medium / low + 必要时替代解释（压缩或运动模糊也可能造成同类现象）
```

**模糊反馈排查入口**（用户只给一句模糊反馈时先查哪几项）：

| 用户说 | 先查 |
|---|---|
| "人物有点假" | 重量/接触/关节 → 表演目标/视线 → 摄影机同步 → 跨帧身份 |
| "画面很平" | 主体层级/前中后景 → 明暗分离 → 色彩主次 → 机位角度/遮挡 |
| "没有电影感" | 先确认目标类型，再查镜头叙事动机 → 光色层级 → 动作与摄影机节拍；**不用黑边/颗粒/浅景深当诊断** |
| "运镜很 AI" | 等速运动 → 突兀启停 → 不合理预判 → 视差错误/主体锁死/背景形变 |
| "情绪不够" | 情绪过程 → 视线对象 → 反应时间 → 景别信息量/镜头距离 → 声音支持 |

**判断纪律**：变化 ≠ 错误——先结合提示词、分镜、参考图判断是否创作意图（风格化发光/拖影/转场/变装先按意图解释，只有破坏可读性、时序或主体结构才判缺陷）；风格本身不是缺陷——先识别风格意图，再判断视听是否服务该意图；不把"85mm 必然有情绪""浅景深必然有电影感"类经验说成定律。

## 返修成本阶梯（Remediation cost ladder，2026-09-18 AI导演审片库吸收）

Retry ladder 之前先过成本阶梯，**重生成是第 3 条路不是默认路**：

1. **剪辑规避**：问题在非必要头尾、重复动作或可删停顿 → 直接剪掉；
2. **后期修复**：文字、Logo、水印、局部遮盖、声音电平、简单色彩或稳定问题 → 移交后期（对接 Stage 4）。**后期手段速查（2026-10-08 AI后期修复库吸收）**：轻微闪烁/抖动→去闪去抖稳定；流畅度不足→插帧；清晰度不足→超分+细节增强/降噪；口型不匹配（配音路线）→唇形同步；表情/视线弱→表情驱动补拍；背景不合→绿幕抠像换背景+光线/色彩/透视/运动四项匹配；局部伪影/穿模帧→修补修复。**边界铁律：后期只修 aesthetic/material 级缺陷——identity（换脸/换装）与 action（动作错误）级禁走后期硬修，必须回生成端重投（对照修复优先级链：先修身份动作，画面稳定后才允许碰风格）**；
3. **局部重生成**：短时人脸/手脚/物体交互/纹理爬行或单一动作损坏 → 进下方 Retry ladder；
4. **整镜替换**：主体身份、空间或叙事在大部分时长持续失效 → `alternate-route` / `drop/rewrite`。

**返修包字段**（选择重生成路径时必须给全，缺项=返修方案不完整）：

- 目标片段 + 建议保留的前后边界；
- 需锁定的角色、服装、道具、场景与镜头特征；
- 正向约束：明确期望的可观察结果；负向约束：只针对已观察到的问题，不堆通用负面词；
- 验收点：返修后需重新确认的 2-4 个可见条件（写入该镜头的 shot lock 记录）。

**返修提示词模板**（与 stage3 分镜模板同源，单镜返工用）：

```text
保留：{稳定参考帧中的角色、服装、场景、构图与光线}
动作：{清晰描述动作起点、接触、运动路径和终点}
约束：{针对问题的稳定结构与连续关系}
避免：{本次实际发生的换脸、粘连、乱码或融化}
首尾：从 {起始状态} 自然过渡到 {结束状态}
```

## Retry ladder

> 执行前提：已过返修成本阶梯、确认走"局部重生成"路径。专业参数受平台限制无法直接控制时（焦距/光圈/运动曲线），翻译成画面关系与动作描述，不承诺平台一定支持。

**单变量纪律与修复优先级（2026-10-03 shuohao iteration-doctor 库吸收）**：
- **每次重试只改一个主变量**——一次改多处，缺陷归因不可能，也说不清新版本为什么好/坏。
- **修复优先级链**：`identity → action → camera → aesthetic → material → rhythm`——先修身份再修动作再修镜头，画面稳定后才允许加风格；顺序颠倒（先调色调后修换脸）= 白烧额度。
- **二次失败升级取证**：同一失败族（同根因的表现）重试两次仍失败 → 暂停打补丁，升级为**取证**（抽帧对照/换最小提示词复现/查平台能力快照），拿证据再写下一版；**禁止用更多形容词回应重复失败**。
- **下一版观察点**：每个重试版本注明"本版优先验证什么"（如：眼神是否成立/接触帧是否可读），回收时先查这一点。

1. Correct an explicit contradiction or missing must-have.
2. Reduce the shot to one primary action and one camera behavior.
3. Improve/replace the reference asset or bind first/last frame.
4. Split the shot or move exact timing/text/effects to post.
5. Switch model/route.
6. Rewrite coverage while preserving the story beat.

Stop after two targeted retries on the same diagnosed cause unless new evidence justifies another. Record salvaged use: insert, reaction, transition, plate, audio-only or background layer.

## Shot lock

A shot is locked only when selected take, prompt/profile, continuity out-state, edit notes and remaining post fixes are recorded. Build the rough cut from locked or explicitly temporary shots, then run:

- missing beat/coverage scan;
- duplicate information scan;
- continuity and screen-direction scan;
- dialogue and action timing scan;
- audio gap scan;
- runtime and rhythm scan.

Only the locked rough cut advances to final post-production.

## 行为验证案例（最小集，2026-09-29 补）

- 输入：用户发来一段 take 说"走路有点飘" → 触发审美翻译层，证据链六段式输出（可见证据带时间范围 / 专业判断=脚底锁定与重心起伏未形成同一套重量反馈 / 修改方向=锁定脚底接触帧+每步重心下沉）+ 置信度标注；处置=retry（局部重生成），返修包字段给全。
- 输入：八维全过但用户说"没电影感" → 先确认目标类型，十维度只展开影响最大三项；不用"黑边/颗粒/浅景深"当诊断；审美诊断与八维处置分开呈现。
- 输入：一条 take 轻微换脸但剧情可读（2026-10-03 补，三级严重度） → 判 `Major`（非 Blocking——身份漂移发生在非关键帧且可剪辑规避），归因层=参考图（非"模型不行"），处置=accept-with-post-fix；同一镜头若面部持续不可认 → 升 `Blocking`，不可锁定。
- 输入：同一镜头"手指粘连"连续两版重试仍出现（2026-10-03 补，二次失败升级） → 不再出第三版提示词，升级取证：抽帧对照两版失败帧是否同根因 → 换最小提示词复现 → 查平台能力快照；拿证据再写下一版，且每版只改一个变量。
