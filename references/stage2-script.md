# Stage 2 剧本创作（大纲 → 分场剧本）

> 输入：用户点子、大纲、已有剧本或项目档案；材料够写时直接进入，不要求为短片先补完整工程档案。
> 输出：用户所求范围的分场剧本或诊断。编剧核心统一加载 [screenwriting-craft](../../screenwriting-craft/SKILL.md)；它负责故事、人物、场景、台词和改稿。本文件只补导演项目的制作约定与交接。
> 留存型连载另读 `short-drama-engine.md`；其数值基线不用于所有短片。

## 0. 项目档案维护

原创可创造设定；原作事实、用户限制、已确认内容与新提案分开。已有档案就更新同一份，不建竞争版本；小型纯剧本任务无需先建档案。缺少关键事实时只询问真正影响创作方向的部分。

## 0.5 开写准备（按任务缩放）

按编剧技能的片型与入口路由准备；人物、因果、信息与场景方法不在此重复定义。开写前至少知道本次交付、用户限制和当前处境；不要求微故事填满人物创伤、信息矩阵和伏笔编号。

**时间表示同源**：出现总时长、场次时间码、beat、OP/ED 时核对同一设计预算，并标明设计估计或实测。交叉剪辑显式声明同时/稍后/闪前/主题并置，不仅凭色调推定同时。

## 1. 写戏规范

场景卡、表演五支柱、动作与潜台词写法统一见编剧技能的「场景与台词」。不再使用每场固定换招次数、情绪强度上限或“压住总比释放高级”的通用判定。

本套件继续用 `第X场｜内/外·地点·时间`；动作独立成段，台词用 `角色：台词`，已有用户格式优先。

**声音交接保留现有项目约定**：本套件历史约定 OS=内心独白、VO=画外说话/叙述；同时写明中文声源含义，避免与其他制作规范混淆。角色内心独白不做口型；进 Stage 3 时执行其「台词口型同步纪律」。不得擅自改原台词、说话者或声音类型。

## 1.5 爽点设计（仅项目明确要留存型爽剧时加载）

本节的配额、秒数和释放方式是该类项目的可调配方，不是剧情通用标准；“动态漫”只是媒介，温情、悬疑或观察式作品不因此强制爽点。

**核心公式**：节奏起伏 = 压抑/铺垫（慢）→ 爆发/反转（快）。**无压抑则无爽感**——爽点的高度由前期压抑的深度决定。

**爽点三类型**（单集配置：1 个核心爽点 + 2-3 个小爽点）：

| 类型 | 公式 | 适用 |
|---|---|---|
| 情绪释放型（新手优先） | 主角受委屈/被误解/陷困境 30-60s → 反抗/自证/被认可释放 | 通用 |
| 反转打脸型（高记忆点） | 反派嚣张/他人轻视 20-30s → 隐藏实力/关键证据/反转设定 | 爽剧主力 |
| 高光时刻型（系列剧必备） | 冲突爆发主角陷绝境 → 突破极限/隐藏技能/正义选择 | 立人设、拉追更 |

**避坑四律**：
1. **爽点必须有铺垫**——突然开挂 = 观众无感，前期要埋伏笔道具/细节。
2. **爽点不能与人设冲突**——高冷角色不靠搞笑释放，用"克制但炸裂"（眼神杀+简洁台词+画面升级）。
3. **爽点必须视觉化**——禁止只用台词说"赢了"，要给画面结果（对方倒地+主角站立）。
4. **爽点不能过载**——核心爽点给最强视听资源，小爽点降档，全给 = 全平。

**冲突密度**：每 45 秒至少 1 个小冲突（肢体/言语/心理三选一），每集 1 个核心冲突。无变化的段落可能削弱该类项目的节奏；具体留存效果需实测，不承诺固定秒数决定流失。（2026-09-17 注：本条为**留存驱动短剧的配置基线**，按项目节奏档案调整——见 `short-drama-engine.md`「Runtime profile」；电影/短片/温情向不适用固定密度公式，用因由、类型和呼吸判断。）

**爽点后留白**：强爽点后留 3-5 秒「无台词+微动态」（反派愣住、嘴角抽搐、镜头缓拉远、音效短暂静音后剩风声）——让观众消化情绪，也给下一个节拍蓄力。

## 1.6 时长、对白与人物状态硬校验（完稿必过，2026-09-17 前向测试回写）

1. 先保留用户原台词并继承目标时长及允许误差。参考片、实际音轨与桌读优先于字数估算，估算不构成念白物理下限；具体规则见 stage3「台词时长校验」。
2. 在用户预算内组织念白、动作、反应、转场与必要留白，可并行部分不机械相加。不能凭固定字速判断数学上不成立，更不能据此改词或加全片时长；设计与实测区别标明，真实冲突按 stage3「台词时长校验」处理。
3. 汇总 `OP + 各场 + ED` 与文首声明总时长双向核对；旧时间码、附录结论或注释残留都算版本未收敛，不得标"锁定"。
4. **人物结局用明确状态机**（`存活 / 失踪 / 被拖走 / 困住 / 推定死亡 / 确认死亡`）：正文未确认死亡时，预告、附录与营销文案一律不得私自升级成"死"（2026-09-17《熄灯镇》EP2 状态污染事故回写）。

## 2. 每集片头片尾（OP/ED）设计（项目需要节目包装时）

**节目化 OP/ED 仅当项目已选择该格式时启用**，不是“多集”就自动需要。以下高能快切、怪物、声音腐化、预告卡等保留为既有恐怖/高能系列的制作配方；只在该项目约定下执行，其他题材另按其调性设计。纯剧本、温情短片、观察式作品不强加片头片尾。

### OP（片头，4-6s）—— OP 设计纪律（2026-09-15 三轮实测定稿）

- **第一帧就是本集最具冲突/最刺激的画面**（2026-09-15 三轮实测两轮被否后二爷定调）：OP 不做铺垫、不做温情、不做氛围——直接上本集的怪物奇观/追逐/恐惧顶点素材，按冲突排序组装（怪物奇观→追逐动态→人的恐惧→余波怪象）。温情对比、日常铺垫全部让位。
- **声音要有"声音签名"，不许通用恐怖音效**：OP 的音频弧线必须绑定本集独有的声音机制（如 EP2=一首欢快的歌被当场撕成走形版），先给 0.5s 正常状态再当场腐化——腐化过程本身就是听觉钩子；重低音落点留给剧名。
- **组装纪律**：①前 3 秒必须有声音事件（音效暴击/骤停/腐化）；②每切 ≤1.5s，快切由剪辑台完成，模型不做段内切；③OP 素材全部复用本集正片已生成的最强镜头（结果前置——复用高能素材≠回放，"平"才是原罪）；④钩子字幕只留 0-1 句收口（多余文字层与画面抢注意力）。
- **正文跟着 OP 走**（二爷定调）：OP 先行立项——OP 对观众承诺的奇观与冲突，正文必须偿还；OP 过审后再按 OP 的承诺重排正文结构（恐怖段前移/铺垫压缩），不是让 OP 迁就现有正文。
- 全剧统一**声音记忆点**保留（一声开灯/一句口头禅/一个音效），每集复用。
- **怪物表现力=姿态违背，不是行走**（2026-09-15《雾山精神病院》第1/2/7/8集逐帧对标验证）：爆款 AI 恐怖短剧从不让怪物"正常连续走路"（AI 步态=木偶感根源）——每个怪物镜头是一个**姿态违背的单一瞬间**：倒挂天花板、贴墙攀爬、四肢着地蜘蛛爬、躯干拧转、向镜头扑（charge at camera）、局部肢体特写（手滑扶手/脚印行走）。怪物位移靠**微切跳位**（0.2-0.6s 一切，每切近一步）与**扑镜构图变化**完成，不靠模型生成连续步态。高潮处用微切 burst（0.2-0.34s 连切 3 个以上）。
- **怪+人同框对立是恐怖短剧的第一构图**：人做正常动作（跑/退）在前景，怪做姿态违背在纵深，对立压在**同一帧**里——比怪物 solo 和正反打都狠（对标：EP1 180.8s 女主背对镜头对峙怪物群纵深远景）。
- **主观恐怖三机制（2026-09-16 v7《回头》二爷验收"总算有那味儿了"实证）**：当"展示恐怖"（第三人称看怪物追她）不够吓人时，升级为"施加恐怖"——①**POV 威胁指向自己**：镜头=观众的眼睛在狂奔（画面下缘只带双手虚影+袖口一角），喘息贴麦像观众自己的呼吸；②**怼镜+瞬移失控感**：怪物两次冲向镜头（第二次半臂距离局部失焦），配合"回头它在身后→转回来已在面前"的急甩瞬移；③**未完成动作**：嘶吼张口瞬间画面被"磁带绞碎"（拉丝/卡帧/撕裂，尖叫同步失真绞碎）——脑补比展示可怕。配套武器：**黑屏耳语**（全静 0.2s→右偏 70% 气声哼歌，人声实录禁 TTS，黑屏=它就在观众的屏幕黑里）、**媒介腐化**（声音走形机制长出视觉形态）。双声道分离：喘息偏左/嘶吼居中砸脸/耳语右偏 70%。
- **文字层做成"档案卡"，剧名压帧不黑场**（对标《雾山》签名做法）：钩子文字不是一句散字幕，是**结构化档案卡**（地点+状态/名称+危害程度+消除方式+当前状态，红白双色粗黑体压画面左下）；剧名直接压在第 2-3 个内容镜头的画面上（大白字+红色英文小字），不切黑场单独出。熄灯镇系对应物=**生存法则档案卡**。

### ED（片尾，4-8s）—— 下集爆点预告段，默认进分镜生成

- **ED 主体同样是原创生成的下集预告画面**（4-8s）：把下一集最大的爆点"拍掉一半"——只见结果不见过程（如墙皮鼓起脸形轮廓但不破皮），不是本集画面回放。
- **字卡降级为落款**：法则卡/金句卡/NEXT EPISODE/作者卡合并压在生成画面切黑之后（每卡 0.5-1s）或字幕贴片；预告声线（角色配音一句）压在生成画面上。
- **系列化记忆点**保留：全剧固定一个每集必出的卡位（如"生存法则"系列），培养追更仪式感；NEXT EPISODE 卡面必须标 "NEXT EPISODE" 字样——防切片传播被当正片穿帮。

### 纪律

- **形式全剧统一，每集只换内容不换形式**（声音记忆点、卡位、字体调性保持一致）。
- **OP/ED 的画面作为正式生成段写进分镜脚本**（S0/末段编号；OP 各切按 ≤1.5s 独立短段生成，高能切可复用正片素材）；文字内容与音乐 cue 点写进剧本对应位置（带时间码标注）；Stage 4 由后期制作包归拢字卡清单与音乐参考（见 stage4-postpack.md）——后期负责快剪组装、钩子字幕贴字与混音。
- 单片（非季播）可只保留 ED 钩子段+金句卡，OP 从简。
- **独立片头/片尾包装片与上面分流（2026-09-16 AniShort H3 案例库吸收）**：本节的 OP/ED 是「正片之外的节目段」（复用正片素材+剪辑台快剪）；**独立成片的片头（title sequence，含署名卡/字体系统/构建式片名）与品牌片尾定版（brand ending）**不走本节组装逻辑，创意设计走 `references/title-design.md`（片头五层结构/署名卡系统/字体三级/转场来源化/音乐四段式/片尾三种定版模式，MiniMax H3 单次生成 ≤15s 硬约束）——剧本阶段只需立项声明"本片需要独立片头/片尾"，具体设计在 Stage 3 分镜时按该文件执行。两边的收尾纪律（定格时长下限/音乐终止式/切出方式显式）通用。

## 3. 台词七维质检

统一使用 [screenwriting-craft](../../screenwriting-craft/SKILL.md) 的「场景与台词」第 5 节，那里同时维护规则、示例与自检。七维检查用于识别问题，不要求每句都含潜台词、同时做两件事或每集凑金句。短促狠话只是一种语感，用户原台词与定点修改锁优先。

## 4. 剧本体检与圆桌会诊

普通诊断按编剧技能的「改稿与证据式诊断」直接执行。只有用户明确要圆桌时，才模拟几种有意义的观看视角；明示这是同一模型的角色化分析，不是多位真实专家独立投票。无需展示名单后再等“开始”。

每条指出原文位置、问题、影响、最小修法与保护项；只诊断时不应用修改。严重度按证据与影响判断，不按几位模拟评委提到计票。不强制唯一根因、每位必找问题、固定篇幅或资历自述。只有梗概就评估梗概，不捏造场号与台词。

**最小行为案例**：“只看看这两句台词为什么假”→局部证据诊断，正文不改，不启动全剧圆桌或制作面板。

## 5. 黄金前 3 秒与集尾断章（项目选择留存型连载配方时，2026-09-16 short-drama-factory 库吸收）

本节只在项目采用这一配方时使用；连载形式本身不构成启用条件。秒数、钩子母型和断章次数服从项目约定，温情或观察式连载不强制套用。

> 与第 2 节 OP/ED 设计分工：OP 是「片头节目段」的组装规范；本节管**正文第 1 个镜头拍什么**（前 3 秒）与**正文最后 1 拍切在哪**（断章）。两者不冲突——正文前 3 秒原则同样约束 OP 素材排序。

### 5.1 黄金前 3 秒钩子（五母型选一）

前 3 秒必须见冲突、见危机、见反常——**严禁开场铺垫**。禁令四条：早晨起床拉窗帘 / 行驶空镜超 2 秒 / 大段旁白交代背景 / 无意义闲聊倒水。

| 母型 | 核心刺激 | 变体示例 |
|---|---|---|
| 生死绝境 | 物理威胁+紧迫感 | 刀尖顶咽喉、扳机缓扣；病危通知书「还差十分钟」；悬崖边手指被踩 |
| 极端羞辱 | 憋屈感+代入愤怒 | 现金扔泔水桶「用嘴叼出来」；婚礼上婚戒被踩碎；年会坐狗食盆旁 |
| 身份暴涨/暴跌 | 认知冲击 | 离婚扫地出门→门外财阀跪迎；保洁亮 51% 股权印章；乞丐破碗底刻龙王令 |
| 物证背叛 | 信任崩塌（女频强） | 传家玉镯戴在闺蜜手上；亲子鉴定 0.01%；顶罪出狱撞上男友与亲妹婚礼 |
| 反常理悬念 | 好奇心（悬疑/脑洞） | 「这个家里除了我所有人都在装死」；10 年后发来的短信；镜中的自己突然笑了 |

### 5.2 集尾断章（四大公式选一，每集必有）

需要断章的连载标出实际断章动作/台词；“下滑立即解锁”等平台引导仅在项目明确需要时附加，不自动写进剧情。

| 公式 | 原理 | 写法要点 |
|---|---|---|
| 身份掉马前一秒 | 好奇心拉爆 | 马甲被识破的**刹那**切断——反派看清印章/DNA 报告的一瞬，僵在原地（黑屏） |
| 物理危机悬停 | 生存悬念 | 伤害造成前 0.1 秒切断——男主双手刚够到女主衣角的瞬间（黑屏） |
| 反差金句落地 | 情绪高潮留白 | 全场嘲讽压到极致→主角一句震碎三观的台词→全场死寂停格（黑屏） |
| 绝境二选一 | 道德困境 | 反派逼选+读秒倒计时——「左边是你亲妈的氧气管，右边是你妹妹的录取通知书，十秒选」（滴答声，黑屏） |

## 6. 多集连写台账（连载必建，2026-09-16 short-drama-factory 库吸收）

> 多集连写不崩的唯一保障。**无台账不开写**：连写/续写每集写前必读台账、写后必更新。台账与项目档案分工——档案管「设定」，台账管「状态随集数变化」。剧本正文与台账冲突时，停下向用户确认哪边改。

四类账（一个项目一份，随剧本文件交付）：

| 账 | 列 | 铁律 |
|---|---|---|
| 伏笔账 | ID / 内容 / 埋于第几集 / 拟收第几集 / 状态(埋·养·收·废) | 每集登记新埋伏笔；回收改状态记收法；密度参考每 10 集 ≥2 埋 1 收 |
| 人物账 | 角色 / 首次出场 / 当前状态(存活·死·失踪·身份) / 与主角关系现值 / 最后变动集 | **死人不能再开口**；状态变化必须记集号与触发事件；新角色先入项目档案建档再给台词 |
| 道具账 | 道具 / 持有者 / 当前状态 / 变动集 | 参与卡点/反转的关键道具每次易手、损毁、出示记一行；断章用到道具特写前必核对当前持有者 |
| 世界观规则账 | 规则 / 确立集 / 引用集 / 是否被违反 | 重生/系统/规则怪谈类必立：能力边界、代价、禁忌各成行；违反已立规则=剧本 BUG |

读写规程（连写主循环）：读台账四类 → 对齐本集在结构/回合中的位置 → 写单集（前3秒+本集冲突拍+断章）→ 自检 → 更新台账（新伏笔/人物变动/道具易手/规则引用逐条落账）。台账更新不是可选项，没落账=本集未完成。单集内「上集衔接」以台账为准，不凭记忆复述前情。

## 6.5 长剧本分批输出纪律（2026-10-08 剧本生成助手库吸收——单部长剧本超单次输出上限时适用，与第 6 节多集台账互补：台账管跨集状态，本节管单部内的输出截断）

1. **禁止压缩写烂**：需求体量超单次输出上限时，必须分批输出，不为了一次塞完而压缩剧情密度、砍伏笔、潦草收尾。
2. **批末三件套**：每批结束标注【待续】，并附①本批剧情进度小结（写到哪场、发生了什么）②当前未回收伏笔清单（连写项目与伏笔账同步）③下一批入口（从哪场继续）。
3. **续写前强制重读**：动笔下一批前重读人物小传+大纲+伏笔清单（连写项目含四类台账），校验人物标志性特征、道具状态、昼夜时序无漂移，确认后再续；发现漂移先修正对齐，不带着错账往下写。
4. **按授权续写**：已要求完整稿时，在可用输出或文件中继续完成，不逐批重复索取许可；确因上下文或输出上限中断，保留未完成标记与续写入口，不用梗概冒充完成稿。

## 7. 发布要求（用户要面向具体平台交付时）

按目标平台现行公开规则核查实际内容，标明来源与核查日期；未核验不宣称必过审或“一票否决”。视觉尺度与表达方式可以按受众和用户需求调整，但换几个词不等于内容合规，也不能为了预设平台偏好擅改用户剧本。

## 8. 完稿出口

- 编剧技能的故事/场景/改稿检查按本次任务已完成，诊断建议未冒充应用修改。
- 仅当项目选定 OP/ED 时检查第 2 节；仅留存型连载检查第 5 节。
- 连写项目同步第 6 节台账；有时长声明时过第 1.6 节；分批内容明确完成范围。
- 涉具体发布平台时核查其现行规则；第 7 节只是既有检查提示，不构成最新政策或通过保证。
- 用户只要剧本/诊断，到此交付；不得自动打开制作面板。


只有用户要求进入制作时，才将剧本版本、确认状态、最新项目档案、时长与允许误差交给 Stage 3。已明确时长直接继承；缺少的制作参数由 Stage 3 原版面板收集。本阶段自检不等于用户已锁定剧本。
